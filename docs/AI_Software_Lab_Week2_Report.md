## 1. 개발 개요 및 목표 (무엇을 개발하였는가?)

### 1.1 개발 동기 및 목적
맥북의 Force Touch 트랙패드는 내부에 정밀한 햅틱 피드백 액추에이터(Taptic Engine)를 탑재하고 있습니다. 일반적인 상태에서는 클릭 느낌을 전달하는 용도로만 사용되지만, **"노트북에서 재생되는 유튜브, 음악, 영화 등의 소리를 실시간으로 분석하여 손끝으로 비트와 타격감을 느낄 수 있는 햅틱 피드백 앱"**을 만들면 청각 장애인을 위한 촉각 보조(Accessibility)나 미디어 감상 시의 몰입감을 극대화할 수 있겠다는 아이디어에서 출발했습니다.

### 1.2 핵심 구현 기능
1. **시스템 오디오 실시간 캡처**: macOS 13+의 `ScreenCaptureKit`을 활용해 별도 가상 드라이버(BlackHole 등) 없이 시스템 전체 사운드를 스트리밍으로 캡처.
2. **초저지연 DSP 주파수 분석 (Accelerate vDSP)**: 1024-point Hann 윈도우 기반 실시간 고속 푸리에 변환(FFT)을 수행하여 베이스(20~150Hz), 미드(150~2kHz), 풀 스펙트럼 대역별 에너지 및 순간 과도 신호(Onset/Transient)를 5ms 이내로 검출.
3. **전역 햅틱 엔진 (MultitouchSupport C-Bridge)**: 다른 앱(Chrome, Safari 등)을 사용하는 백그라운드 상태에서도 전역으로 트랙패드 액추에이터를 제어하는 C 브릿징 및 과열/버징 방지를 위한 하드웨어 쿨다운(Cooldown Debounce) 스로틀링 구현.
4. **macOS 메뉴바 UI (SwiftUI)**: 상태 표시줄에 상주하며 실시간 오디오 에너지 레벨 및 임계값(Threshold) 시각화, 햅틱 감도/쿨다운/주파수 대역 조절 슬라이더 제공.

## 2. 개발 과정에서 원했던 결과와 실제 결과가 달랐던 문제점

에이전트와 함께 개발을 진행하면서 총 **3가지 주요 문제(Discrepancies)**가 발생했습니다:

### 문제 1: AppKit 공식 API(`NSHapticFeedbackManager`)의 백그라운드 동작 불가
- **원했던 결과**: 사용자가 유튜브를 시청하거나 게임을 하는 등 다른 창을 보고 있을 때도 사운드에 맞춰 트랙패드가 울릴 것.
- **실제 결과**: Apple의 공식 AppKit API인 `NSHapticFeedbackManager`는 **해당 앱의 윈도우가 First Responder(활성화된 창)일 때만 작동**하도록 설계되어 있어, 앱이 메뉴바에 상주하거나 백그라운드로 가면 햅틱 피드백 신호가 시스템에 의해 자동으로 무시(Silent Drop)됨.

### 문제 2: vDSP FFT 스펙트럼 계산 시 주파수 누설 및 비정상 에너지 증폭
- **원했던 결과**: 60Hz 저음(Bass) 사인파를 입력했을 때 베이스 대역(20~150Hz)에서만 에너지가 감지되고, 미드 대역(150~2kHz)에서는 에너지가 거의 감지되지 않아야 함 (명확한 대역 필터링).
- **실제 결과**: TDD 테스트 중 `testPure60HzSineWaveTriggersBassBandNotMid`에서 미드 대역 에너지가 `0.517`까지 비정상적으로 높게 측정되며 테스트 실패 (`0.517 is not less than 0.1`).

### 문제 3: 트랙패드 하드웨어 특성과 연속 진동 시의 이질감
- **원했던 결과**: 소리의 파형을 그대로 진동으로 변환하여 연속적인 우퍼처럼 동작할 것.
- **실제 결과**: 트랙패드의 전자석 액추에이터는 '클릭' 시뮬레이션용으로 설계된 단발성 펄스 구동 방식이어서, 고주파수 신호에 맞춰 초당 수십 번 이상 연속 구동할 경우 소음(덜덜거리는 잡음)과 드라이버 스로틀링이 발생함.

### 문제 4: macOS 팝오버(NSPopover) UI 텍스트 및 레이아웃 잘림 (Clipping)
- **원했던 결과**: 상단 메뉴바 팝오버를 열었을 때 모든 라벨("Energy Level", "Threshold", "Pattern", "Full Spectrum")과 버튼이 잘림 없이 깔끔하게 표시될 것.
- **실제 결과**: 초기 팝오버 실행 시 좌측과 우측이 약 20px씩 잘려 "ergy Level", "eshold", "ttern", "Full Spectrur"로 텍스트가 잘리는 현상 발생 (`스크린샷 2026-09-10 10.26.56.png` 참고).

### 문제 5: ScreenCaptureKit 캡처 시작 후 브라우저 음악 재생 시 햅틱 미반응
- **원했던 결과**: 'Start System Capture' 버튼을 누르고 브라우저(유튜브 등)에서 음악을 틀었을 때 실시간 에너지 미터가 올라가며 트랙패드 햅틱이 울릴 것.
- **실제 결과**: 캡처를 시작하고 음악을 재생해도 실시간 에너지 레벨 미터가 0%에 머물고 햅틱이 전혀 반응하지 않음.

## 3. 원인 분석 (왜 발생했다고 생각했는가?)

1. **원인 1 (AppKit 보안 및 포커스 정책)**:
   - Apple은 백그라운드 앱이 사용자의 의사와 무관하게 트랙패드나 마우스를 흔들어 사용자 경험을 방해하는 것을 막기 위해 `NSHapticFeedbackPerformer`의 권한을 엄격히 현재 활성 윈도우로 제한해 두었기 때문입니다.
2. **원인 2 (Accelerate vDSP 실수 및 복소수 메모리 패킹 & 정규화 불일치)**:
   - 실시간 오디오 버퍼를 `vDSP_ctoz`를 통해 분할 복소수(`DSPSplitComplex`)로 변환할 때, 포인터 캐스팅과 스트라이드(Stride) 설정이 누락되어 샘플이 건너뛰어지며 고주파 앨리어싱(Aliasing)이 발생했습니다.
   - 또한 FFT 크기 $N$에 따른 전력 스펙트럼 스케일링 팩터가 $4.0 / N^2$ 대신 단순 $1/(2N)$으로 적용되어 주파수 누설 에너지가 과대평가되었습니다.
3. **원인 3 (액추에이터의 물리적 공진 주파수 및 펄스 한계)**:
   - 스마트폰의 ERM/LRA 진동 모터와 달리, 포스 터치 트랙패드는 순간적인 임펄스(Dirac Delta에 가까운 클릭감)를 생성하도록 튜닝되어 있으므로 연속적인 음향 파형 추종이 불가능합니다.
4. **원인 4 (AppKit의 NSPopover 고정 프레임 및 SwiftUI Picker 기본 2-컬럼 라벨)**:
   - macOS AppKit 환경에서 `Picker`는 기본적으로 좌측에 라벨("Band", "Pattern") 컬럼을 생성하므로 내부 콘텐츠의 최소 고유 너비(Intrinsic Width)가 약 360px 이상으로 확장되었습니다.
   - 반면 `NSPopover`의 창 크기는 `320px`로 하드코딩되어 있어, SwiftUI가 오버플로된 콘텐츠를 가운데 정렬하면서 좌우 약 20px씩 잘려 나가는 클리핑 현상이 발생했습니다.
5. **원인 5 (CoreMedia의 Non-Interleaved 오디오 버퍼 리스트 크기 부족 오류 -12737)**:
   - macOS `ScreenCaptureKit`은 시스템 오디오를 2채널 Non-Interleaved(좌/우 버퍼 분리) 방식으로 전달합니다.
   - 따라서 `CMSampleBufferGetAudioBufferListWithRetainedBlockBuffer` 함수는 2개의 개별 버퍼 구조체를 담을 수 있는 40바이트의 `AudioBufferList`를 필요로 합니다.
   - 하지만 기존 코드는 단일 버퍼 크기(16바이트)의 `var bufferList = AudioBufferList()`를 정적으로 넘겨주어, 함수가 매 프레임마다 `-12737` (`kCMSampleBufferError_ArrayTooSmall`) 에러를 반환하고 모든 오디오 데이터를 버리고 있었습니다.

## 4. 해결 및 개선 과정 (어떻게 개선했는가?)

AI 에이전트와 체계적인 엔지니어링 절차(TDD, Spec 구체화, 하네스 지침)를 통해 위 문제들을 단계별로 해결했습니다:

### 해결 1: `MultitouchSupport.framework` C-Bridge 전역 제어 도입
- 공식 AppKit API 대신 macOS 내부 비공개 프레임워크인 `MultitouchSupport`를 `dlopen`과 `dlsym`을 통해 런타임 동적 링킹했습니다.
- `MTDeviceCreateList()`, `MTDeviceGetDeviceID()`, `MTActuatorCreateFromDeviceID()`, `MTActuatorActuate()` C 함수를 호출하여 시스템 포커스 상태와 상관없이 물리 트랙패드(Device ID: `504403158265495834`)에 직접 전역 햅틱 신호를 송출하는 데 성공했습니다.

### 해결 2: 수학적 전력 스펙트럼 정규화 및 주파수 빈 분리 개선 (TDD 기반)
- `AudioDSPAnalyzer.swift`에서 Hann 윈도우 적용 후 `vDSP_ctoz`의 분할 복소수 변환을 올바르게 매핑하고, 전력 스펙트럼 계산식을 진폭 기준 정규화($4.0 / N^2$)로 재구축했습니다.
- 베이스(20~150Hz)와 미드(151~2000Hz)의 경계 빈을 정확히 분리하여, 60Hz 사인파 입력 시 미드 대역 에너지가 `0.096` 이하로 억제되도록 수정했습니다.
- 결과적으로 17개의 단위 테스트(`swift test`)가 모두 100% 통과(Pass)하도록 검증했습니다.

### 해결 3: 온셋(Onset/Transient) 검출 및 쿨다운 스로틀러(Cooldown Throttler) 구현
- 연속 진동 대신 음악의 **킥 드럼, 베이스 어택, 타격음의 순간적인 에너지 급증($\Delta E > \text{Threshold}$)**만을 정밀 감지하는 온셋 검출 알고리즘을 구현했습니다.
- `HapticEngine`에 최소 쿨다운 간격(기본 90ms, 30~300ms 설정 가능)을 강제하는 디바운스 로직을 추가하여, 아무리 소리가 빠르거나 시끄러워도 트랙패드가 깔끔하고 리드미컬하게 '쿵- 쿵-' 박자에 맞춰 타격감을 전달하도록 개선했습니다.

### 해결 4: `.labelsHidden()` 및 `fittingSize` 기반 반응형 팝오버 리팩토링
- 세그먼트 Picker에 `.labelsHidden()`을 지정하여 불필요한 좌측 라벨 컬럼을 제거하고 컨트롤이 전체 너비를 채우도록 개선했습니다.
- 세그먼트 텍스트를 컴팩트하게("Bass", "Mid", "Full") 구성하고 상단에 주파수 범위 설명을 분리 배치했습니다.
- `AppDelegate`에서 `NSHostingController.view.fittingSize`를 동적으로 측정하여 팝오버 크기를 설정하도록 변경함으로써 텍스트와 버튼이 여유 있게 표시되도록 완벽히 수정했습니다.

### 해결 5: `AudioBufferList.allocate` 동적 할당 및 기본 감도 최적화
- `ScreenCaptureKitAudioSource.swift`에서 채널 수에 맞춰 `AudioBufferList.allocate(maximumBuffers: channelCount)`를 동적으로 할당하고 `free()`로 반환하도록 수정하여 에러 코드 `-12737`을 완전히 제거했습니다.
- 브라우저 음악 및 유튜브의 평균 마스터 볼륨 음압에 맞춰 기본 임계값을 45%에서 실용적인 **25%**로, 순간 어택 감도를 0.08에서 **0.04**로 튜닝하여, 브라우저에서 음악을 틀자마자 트랙패드가 즉각 리듬감 있게 반응하도록 개선했습니다. (`swift run HapticBeat --test-capture`로 실제 시스템 오디오 282프레임 캡처 및 햅틱 정상 격발 검증 완료)

### 해결 6: 2D 트랙패드 햅틱 매트릭스(사운드 레이더) & 입력 게인(Input Gain) 제어 구현
- **2D 공간 오디오 레이더(Sound Radar)**:
  - Y축 주파수 매핑: 하단(Low Bass, 20~150Hz), 중앙(Mid Vocals, 151~2000Hz), 상단(High Treble, 2000~20000Hz)을 실시간 Accelerate vDSP 파워 스펙트럼으로 분리 계산하여 네온 오가닉 발광체(Glow Orb)로 시각화했습니다.
  - X축 스테레오 패닝 매핑: 좌/우 채널 RMS 에너지 비율($Pan = \frac{RMS_R - RMS_L}{\max(0.001, RMS_R + RMS_L)}$)을 실시간 산출하여 $[-1.0, 1.0]$ 범위로 오가닉 노드가 좌/우로 반응하여 이동하도록 구현했습니다.
  - 햅틱 동기화 충격파 링: 박자 감지 시 트랙패드 표면에 시각적 펄스 링(Shockwave Ripple)이 확산되어 촉각과 시각이 일치하는 공감각적 피드백을 완성했습니다.
- **입력 게인(Input Gain) 제어**:
  - 음압이 매우 높은 EDM/힙합 음원 재생 시 100% 피크가 지속 발생하거나 조용한 클래식/재즈 음원에서 감도가 낮아지는 현상을 방지하기 위해, FFT 진입 전 `vDSP_vsmul` 기반의 입력 게인(10%~200%, 0.1x~2.0x) 슬라이더를 장착했습니다.
- **UI/UX 간소화**:
  - 실사용 빈도가 낮은 120BPM 데모 버튼과 쿨다운 슬라이더를 제거하고, `ui-ux-pro-max` 다크 모드 HUD 스타일로 세련되고 깔끔한 팝오버를 완성했습니다.

### 해결 7: 멀티터치 실시간 좌표 연동 및 공간 분할 터치 게이팅(Spatial Touch Gating) 구현
- **체감 분리도 한계의 근본 원인 규명**:
  - 맥북 트랙패드는 유리판 전체 아래에 1개의 단일 탭틱 엔진이 장착되어 있어, 하드웨어적으로 특정 부위만 따로 진동시키는 것은 물리적으로 불가능합니다.
  - 또한 기존 로직은 좌우/주파수 분리 분석 결과와 무관하게 비트가 감지되면 트랙패드 모터를 무조건 격발하여, 오른쪽에 손가락을 대고 있어도 왼쪽 소리에 진동이 느껴지는 문제가 있었습니다.
- **멀티터치 접촉 좌표 추적 (`MultitouchTracker`)**:
  - `MultitouchSupport.framework`의 `MTRegisterContactFrameCallback`을 연동하여, 트랙패드 위에 닿아 있는 모든 손가락의 정규화 좌표($X, Y \in [0.0, 1.0]$)를 실시간 캡처하는 서브시스템을 구축했습니다.
- **다중 손가락 공간 일치 게이팅 (`SpatialTouchGate`)**:
  - 손가락이 오른쪽에만 닿아 있을 때 왼쪽 소리가 나면 햅틱 모터를 침묵시키고, 오른쪽 소리가 날 때만 햅틱을 격발하도록 공간 게이팅을 적용했습니다.
  - 사용자가 여러 손가락으로 좌/우 및 상/중/하를 동시에 터치하고 있을 경우, **터치된 영역 중 어느 하나라도 일치하는 음향 이벤트가 발생하면 정상적으로 햅틱이 격발**되도록 다중 터치 합집합(Union) 매칭 알고리즘을 구현했습니다.
  - 팝오버 화면의 2D 가상 트랙패드 위에도 실시간 손가락 접촉 링(Touch Ring)과 터치 개수 뱃지를 렌더링하여 공감각적 정합성을 완성했습니다.

### 해결 8: C ABI 메모리 레이아웃 불일치로 인한 멀티터치 좌표 왜곡 및 이벤트 유실 해결
- **문제 증상 규명**:
  - 실시간 트랙패드 매트릭스에서 손가락을 누른 위치와 전혀 다른 곳에 터치 링이 표시되거나, 터치 이벤트가 간헐적으로 아예 나타나지 않는 현상이 발생했습니다.
- **체계적 디버깅(Systematic Debugging) 기반 원인 분석**:
  - `MultitouchSupport.framework`의 비공개 C 구조체 `MTTouch`는 arm64 macOS에서 8바이트 정렬 규칙을 따릅니다.
  - `frame (Int32)` 필드(0~3바이트) 뒤에 8바이트 부동소수점인 `timestamp (Double)`(8~15바이트)이 오면서 4바이트의 컴파일러 패딩(Padding)이 삽입됩니다.
  - 기존 Swift 포인터 오프셋 연산이 4바이트 정렬을 전제로 작성되어 있어 다음과 같은 치명적인 필드 전이가 발생하고 있었습니다:
    1. **터치 유실 현상**: offset 16은 `state`가 아닌 `pathIndex`(터치 슬롯 번호)를 가리키고 있었습니다. 첫 번째/두 번째 손가락은 슬롯 번호가 0 또는 1이므로, `state == 3 || state == 4` 조건문에서 탈락하여 터치가 무시되었습니다.
    2. **좌표 왜곡 현상**: offset 28은 X좌표가 아닌 `handID`(정수 1 또는 0)를 읽어 X좌표가 0.0 근처로 왜곡되었고, offset 32는 실제 X좌표를 Y좌표로 잘못 읽고 있었으며, 정작 실제 Y좌표(offset 36)는 아예 누락되어 있었습니다.
- **근본 해결 및 TDD 검증**:
  - C ABI 사양과 완전히 일치하는 `MTTouchRaw` 레이아웃을 기반으로 오프셋을 정밀 재조정했습니다 (`state`: 20, `fingerID`: 24, `x`: 32, `y`: 36).
  - 손가락을 뗐을 때 터치 잔상이 남지 않도록 0.3초 무응답 자동 만료 안전장치(Defense-in-Depth)를 추가했습니다.
  - 팝오버 UI 렌더링 주기를 60fps(0.016s)로 격상하고 테두리 인셋(Margin Inset)을 적용하여 1:1 손끝 추적 정합성을 완성했습니다.
  - C ABI 오프셋 검증 단위 테스트(`MultitouchTrackerTests.swift`) 2건을 신설하여 32개 단위 테스트 전원 통과를 달성했습니다.

### 해결 9: 음량/에너지 반응형 실시간 동적 햅틱 강도(Dynamic Intensity) 구현
- **요구사항 및 문제 배경**:
  - 기존의 수동 Haptic Pattern(Light / Medium / Strong) 선택 방식은 재생 중인 음악의 완급 조절이나 악기별 타격감을 살리지 못하고 항상 일정한 강도로만 햅틱이 출력되는 한계가 있었습니다.
  - 사용자의 요청에 따라 수동 강도 선택 피커를 UI에서 완전히 제거하고, 음악의 실시간 볼륨/에너지에 따라 햅틱 세기가 100% 자율 반응하는 동적 시스템을 도입했습니다.
- **적응형 강도 산출 알고리즘 (`HapticEngine.swift`)**:
  - 임계값(Threshold, $T$) 조절 상태에 상관없이 3단계 강도가 균일하게 분배되도록 상대적 여유폭($Headroom = \max(0.01, 1.0 - T)$) 기반 비례 매핑을 적용했습니다:
    - **1단계 · Light (패턴 1)**: $T \le E < T + Headroom \times 0.33$ (잔잔한 베이스, 부드러운 리듬 탭)
    - **2단계 · Medium (패턴 2)**: $T + Headroom \times 0.33 \le E < T + Headroom \times 0.67$ (스네어, 보컬 어택, 일반 비트)
    - **3단계 · Strong (패턴 5)**: $E \ge T + Headroom \times 0.67$ (강렬한 킥 드럼 드롭, 클라이맥스 묵직한 포스터치)
- **UI 시각 연동 및 간소화 (`MenuBarView.swift`)**:
  - 수동 토글을 제거하여 인터페이스를 극대화된 미니멀리즘으로 정리하고, 실시간 반응 상태(`DYNAMIC`)와 직전 격발된 강도 등급(`LIGHT`/`MEDIUM`/`STRONG`)을 뱃지로 표시했습니다.
  - 햅틱 동기화 충격파 링도 강도에 따라 크기(60px ~ 135px), 테두리 두께(1.5px ~ 3.5px), 색상 그라디언트(네온 시안 ~ 골든 오렌지)가 유기적으로 연동되도록 시각화했습니다.
- **TDD 단위 테스트 검증 (`HapticEngineTests.swift`)**:
  - 에너지 대역별 동적 패턴 결정 및 트리거 검증 테스트 4건을 신설하여, 총 **36개 단위 테스트 전원 통과**를 달성했습니다.

### 해결 10: Apple HIG 네이티브 디자인 시스템 기반 UI/UX 전면 리팩토링 (`ui-ux-pro-max`)
- **문제점 진단 및 리디자인 방향**:
  - 기존 UI는 네온 시안, 보라, 오렌지, 군용 조준선(Reticle Crosshair) 등 알록달록한 사이버펑크풍 AI 특유의 요소가 남발되어 있어, macOS 네이티브 유틸리티 앱다운 정갈함이 부족했습니다.
  - Apple의 **macOS 휴먼 인터페이스 가이드라인(HIG)** 및 `ui-ux-pro-max` 디자인 인텔리전스 규칙에 따라, 번잡한 원색들을 전면 배제하고 세련된 애플 특유의 모노크롬 그라파이트/알루미늄 디자인으로 재구축했습니다.
- **실물 애플 트랙패드 룩앤필 구현 (`AppleTrackpadView`)**:
  - **알루미늄 유니바디 & 매트 글래스 질감**: 14px 라운딩의 샌드블라스트 알루미늄 베젤과 0.5px 마이크로 헤어라인 이너 베벨, 깊이감 있는 딥 그라파이트 매트 글래스 표면을 구현했습니다.
  - **차분한 4세그먼트 어쿠스틱 레벨 바**: 형광 구체 대신 macOS 사운드 설정 스타일의 4-segment 미니 레벨 바(Treble, Vocals, Bass)를 배치하여 주파수 에너지를 정갈하게 시각화했습니다.
  - **네이티브 애플 포인터 터치 링**: 반투명 프로스티드 글래스 디스크(Frosted Glass Disc)와 백색 햅틱 코어로 손끝 접촉을 렌더링하여 실제 트랙패드를 만지는 듯한 감각적 일치감을 부여했습니다.
  - **에어드롭/스포트라이트 스타일 햅틱 충격파**: 비트 격발 시 번쩍이던 무지개 링을 지우고, 애플 포커스 링 특유의 깔끔한 백색 글래스 펄스가 부드럽게 확산 후 디졸브되도록 개선했습니다.
- **벤토 그리드(Bento Grid) 기반 그룹화**:
  - 폭 340px의 표준 macOS 팝오버 규격에 맞춰 컨트롤들을 둥근 시스템 인셋 카드(`controlBackgroundColor`)로 논리적 그룹화했습니다.
  - 슬라이더 및 스위치 컨트롤을 컴팩트(`controlSize(.small)`)하게 다듬고, 불필요한 색상 강조를 제거하여 최신 macOS Sequoia/Sonoma 시스템 설정과 완벽한 일체감을 완성했습니다.

## 6. 결론 및 에이전틱 코딩 실습 소감

이번 프로젝트는 단순한 코드 완성을 넘어, **"요구사항 구체화 $\rightarrow$ 아키텍처 설계 $\rightarrow$ 실패하는 테스트(RED) 작성 $\rightarrow$ 구현(GREEN) $\rightarrow$ 리팩토링 및 하드웨어 연동"**의 전 과정을 AI 에이전트와 함께 수행했습니다.

특히 macOS의 백그라운드 햅틱 제약이나 vDSP 연산의 미세한 오차처럼 '에이전트가 처음에 예상하지 못했던 실제 환경과의 괴리'가 발생했을 때, 에이전트에게 맹목적으로 다시 짜라고 하는 대신 **TDD 단위 테스트와 디버깅 스크립트를 통해 원인을 규명하고 단계적으로 하네스를 고쳐나가는 에이전틱 코딩(Agentic Coding)의 가치**를 깊이 체감할 수 있었습니다.
